# Nepali TTS Frontend Contract

This is the integration rule for every Nepali TTS pipeline.

## Canonical API

All model-specific preprocessors must call:

```python
from nepali_frontend import process

result = process(text, profile="real_nepali")
phones = " ".join(result.phone_sequence)
normalized_text = result.normalized_text
```

Do not call `nepali_frontend.g2p.phonemizer.phonemize_text` directly from a
training or inference pipeline. That lower-level API is allowed only for unit
tests, lexicon work, and research comparisons.

## Manifest Stamp

Every training manifest row must include these fields:

| column | required value |
|---|---|
| `text` | original text |
| `normalized_text` | output of `nepali_frontend.process(...).normalized_text` |
| `phones` | space-separated `result.phone_sequence` |
| `g2p_path` | source summary generated by `real_nepali.manifest` |
| `frontend` | `nepali_frontend.frontend.process` |
| `frontend_profile` | usually `real_nepali` |
| `frontend_version` | package version |
| `frontend_warning_count` | integer warning count |
| `frontend_warning_codes` | comma-separated warning summary |

Generate the manifest with:

```bash
python3 -m real_nepali.manifest \
  --in train.tsv \
  --out train.frontend.tsv \
  --profile real_nepali
```

Audit before any model-specific preprocessing:

```bash
python3 -m real_nepali.manifest \
  --in train.frontend.tsv \
  --profile real_nepali \
  --audit-only \
  --verify-phones
```

For final production training, add `--strict-warnings` after the low-confidence
Latin/code-switch warnings have been reviewed.

## Enforcement Point

Each TTS backend should refuse unstamped manifests:

```python
from pathlib import Path
from real_nepali.manifest import audit_rows, read_manifest

_, rows = read_manifest(Path("train.frontend.tsv"))
errors = audit_rows(rows, profile="real_nepali", verify_phones=True)
if errors:
    raise SystemExit("\n".join(errors[:20]))
```

This gives the same frontend to Piper, Kokoro-style experiments, XTTS-style
fine-tuning, and any future backend. Model code may adapt the phone string to a
backend format, but it must not redo text normalization or G2P itself.

## CI Guard

In training repos, add a grep check that fails direct runtime imports:

```bash
rg -n "from nepali_frontend\\.g2p|import nepali_frontend\\.g2p|phonemize_text\\(" \
  scripts src \
  -g '!tests/**'
```

Any match in a training/preprocessing path should be replaced with
`nepali_frontend.process` or with a stamped manifest generated by
`real_nepali.manifest`.
